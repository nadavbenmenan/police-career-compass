# 🧭 מצפן הקריירה — סוכן AI להתאמת תפקיד

> אפליקציית ווב לשאלון התאמה בין מועמד/ת לתפקידים במשטרת ישראל.
> 17 שאלות, מנוע ניקוד **דטרמיניסטי ושקוף**, ובסוף — 3 התפקידים המתאימים ביותר עם אחוז התאמה ונימוקים.

**🔗 הדגמה חיה:** `https://nadavbenmenan.github.io/police-career-compass/`

## 💡 הבעיה

מועמד שמגיע ליום גיוס נשאל "איזה תפקיד מעניין אותך?" — ולרוב אין לו מושג. יש 22 מסלולים,
לכל אחד תנאי-סף אחרים, והמידע מפוזר. התוצאה: המועמד בוחר לפי מה ששמע מחבר, המגייס משקיע
זמן בהסבר חוזר, והשיבוץ יוצא לא מדויק.

הכלי הזה נותן למועמד נקודת פתיחה מבוססת: הוא עונה על 17 שאלות קצרות ומקבל שלושה מסלולים
שמתאימים לפרופיל שלו — עם הסבר **למה**, ועם העובדות היבשות (הכשרה, דרישות, שכר) לצד כל אחד.

## 🎯 שלושה עקרונות שהמערכת בנויה סביבם

### 1. דטרמיניסטי — לא קופסה שחורה
הדירוג מחושב במנוע ניקוד מבוסס-כללים ב-[`scoring.js`](scoring.js). לכל אופציה בשאלון
יש מטריצת נקודות מפורשת, ואפשר לשחזר כל אחוז ידנית. הכלי לא "מנחש" — הוא סוכם.

לכל תפקיד מחושב אחוז ההתאמה כך:

```
matchPct = round( נקודות שנצברו בפועל / הניקוד המרבי האפשרי לתפקיד × 100 )
```

המכנה נבנה מראש: לכל שאלה נלקחת התרומה הגבוהה ביותר לאותו תפקיד מבין האפשרויות שלה.
שאלה שאף אפשרות בה לא נוגעת בתפקיד פשוט לא נספרת — כך תפקיד נישה לא נענש
על שאלות שאינן רלוונטיות לו.

### 2. כנות נתונים — ה-KB הוא המקור היחיד
כל עובדה על תפקיד מגיעה מ-[`data/roles.js`](data/roles.js) בלבד. הקוד **לעולם** לא מחשב,
משלים או מנחש שכר, משך הכשרה או דרישות. היכן ש-`salary: null` — המסך מציג בדיוק
**"נמסר ביום המיון"**, ולא טווח משוער. בכל כרטיס יש קישור לאתר הרשמי למידע מעודכן.

באנר קבוע מבהיר שזהו כלי הערכה עצמית אינדיקטיבי, ושההחלטה הרשמית מתקבלת רק במיון.

### 3. תמיד ממליץ — ושקוף לגבי מה שנחסם
לתפקידי הליבה (סייר, משל"ט, בלש, חוקר, סייר תנועה) אין תנאי-סף חוסמים, ולכן תמיד
יוחזרו לפחות 3 המלצות — גם לפרופיל שנחסם בכל המסלולים הייחודיים.

במקביל, תפקידים שנחסמו בתנאי-סף אך קיבלו התאמה גבוהה מוצגים בבלוק נפרד עם **סיבת החסימה**
(למשל: "יס\"מ — רובאי 05 ומעלה"). זו שקיפות, לא הבטחה: המשתמש רואה מה קרוב אליו ומה חסר לו.

## 🧠 איך זה עובד — הזרימה

```
תשובות המשתמש
      ↓
buildProfile()      דגלי פרופיל: רובאי, תואר, חוסן, ערבית, סטטוס
      ↓
computeEarned()     סכימת נקודות בפועל לכל תפקיד
computeMaxScores()  הניקוד המרבי האפשרי לכל תפקיד (המכנה)
      ↓
checkGates()        תנאי-סף חוסמים → עובר / נחסם + סיבה
      ↓
דירוג               אחוז יורד → ניקוד גולמי → priority
      ↓
top3 + blocked + נימוקים
```

**הנימוקים** ("למה זה מתאים לך") נגזרים ישירות מהתשובות: המנוע מאתר את השאלות שבהן
הבחירה תרמה הכי הרבה נקודות לתפקיד, וממיר אותן למשפט בתבנית קבועה — `בחרת: "..."`.
אין כאן ניסוח חופשי ואין הוספת מידע.

## 🗂️ מבנה הפרויקט

```
police-career-compass/
├── index.html          מסך יחיד (SPA), עברית RTL
├── styles.css          נייבי-לבן, mobile-first
├── app.js              ניווט מסכים ורינדור (לא מחשב כלום)
├── scoring.js          מנוע הניקוד — פונקציות טהורות, בלי DOM
├── data/
│   ├── config.js       דגלי הגדרה
│   ├── roles.js        מאגר הידע — 22 תפקידים (המקור היחיד לאמת)
│   └── questions.js    17 שאלות + מטריצת הניקוד
├── test/
│   └── run_checks.js   בדיקות שפיות מחוץ לדפדפן
├── assets/emblem.svg   סמל גנרי לפרויקט (אינו הלוגו הרשמי)
└── ai/app.py           proxy אופציונלי להסבר בשפה טבעית — כבוי כברירת מחדל
```

**אין שלב build ואין תלויות.** הקבצים נטענים כ-`<script>` רגילים (לא modules), כדי
שהאפליקציה תרוץ גם בפתיחה ישירה של `index.html` ב-`file://`.

## 🧪 בדיקות

```bash
node test/run_checks.js
```

18 בדיקות שפיות, ביניהן:

| הבדיקה | מה היא מוודאת |
|---|---|
| שלמות המטריצה | כל `roleId` בניקוד קיים ב-`ROLES`, וכל שער מוכר למנוע |
| "תמיד ממליץ" | פרופיל ריק — ואפילו שאלון ללא תשובות — מחזיר 3 המלצות |
| שערים חוסמים | פרופיל ללא רקע קרבי לא מקבל יס"מ/גדעונים/ימ"מ/מג"ב |
| שערים פותחים | תואר פותח מז"פ, ערבית פותחת סיגינט, סטטוס פותח סטודנט/קצונה |
| דירוג נכון | פרופיל לוחם עילית מחזיר את היחידות המיוחדות בטופ |
| תקינות אחוזים | כל האחוזים בטווח 0–100, ולכל תפקיד יש ניקוד מרבי חיובי |
| כיסוי מלא | **אף תפקיד אינו "בלתי ניתן להמלצה"** — ראה למטה |

אותן בדיקות רצות גם בקונסול הדפדפן כאשר `CONFIG.DEBUG = true`.

### 🔧 סטייה מודעת אחת מהאפיון

האפיון קובע סף דירוג קבוע: `MIN_EARNED_FOR_RANK = 4`. בפועל, כשמצליבים את הסף הזה
עם מטריצת הניקוד, מתגלה שלשני תפקידים הניקוד המרבי האפשרי הוא **3** — נמוך מהסף:

* **מסלולי קצונה** (`officer_track`) — מנוקד רק בשאלת הסטטוס.
* **מסלול אולפן ערבית** (`arabic_investigator`) — מנוקד רק בשאלות הערבית והסקרנות.

המשמעות: שני התפקידים האלה לא היו יכולים להיות מומלצים **בשום שילוב תשובות**. במקרה
של הקצונה זה סותר ישירות את דרישת האפיון עצמו ("שערים עובדים… קצונה לפי סטטוס") —
קצין לשעבר היה מסמן את הסטטוס שלו, עובר את השער, ובכל זאת לא רואה את המסלול שנועד לו.

**הפתרון** ([`scoring.js` → `rankThreshold()`](scoring.js)): הסף נחתך לפי מה שהתפקיד
מסוגל לצבור בפועל — `min(MIN_EARNED_FOR_RANK, maxScore)`. תפקיד כזה ייכלל רק אם המשתמש
צבר את **מלוא** הניקוד האפשרי עבורו, ובנוסף עבר את תנאי-הסף — כלומר דרישה מחמירה יותר,
לא מקילה. הכוונה המקורית של הסף (למנוע מתפקיד נישה לקפוץ ל-100% על סמך מעט מידע) נשמרת.

לא שונו נתוני ה-KB ולא מטריצת הניקוד — רק אופן החלת הסף. בדיקה ייעודית מוודאת
שהמצב הזה לא יחזור בשקט אם יתווספו תפקידים בעתיד.

## 🚀 פריסה

**GitHub Pages:** Settings → Pages → Branch: `main` → `/ (root)` → Save.
האפליקציה סטטית לחלוטין, ולכן אין מה להגדיר מעבר לזה. `ENABLE_AI_EXPLANATION`
נשאר `false` ובגרסה הפרוסה הכל רץ דטרמיניסטית.

הנתונים כאן אינם רגישים — זהו מידע ציבורי ממרכז הגיוס.

## 🤖 מצב הסבר-AI (רשות, כבוי כברירת מחדל)

הליבה לא זקוקה למפתח ולא לשרת. בנוסף לה אפשר להפעיל שכבה שמנסחת את ההסבר
בשפה טבעית וחמה יותר:

```bash
pip install flask flask-cors anthropic
export ANTHROPIC_API_KEY=...
python ai/app.py
```

ואז ב-`data/config.js`: `ENABLE_AI_EXPLANATION: true`.

השכבה הזו **מנסחת בלבד**. הדירוג, האחוזים והעובדות מחושבים ומוצגים לפניה ואינם משתנים.
המודל מקבל בפרומפט רק את עובדות ה-KB ואת התשובות, עם הוראה מפורשת לא להוסיף נתונים.
אם ה-proxy לא זמין — האפליקציה נופלת בחן חזרה לנימוקים המתבניתיים.

המפתח נשאר בצד השרת בלבד ואינו מוטמע בקוד הלקוח.
